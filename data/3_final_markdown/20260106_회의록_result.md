[상세 회의록] AI 기반 조직관리 PoC 개발 및 R&R 논의
일시: 2026년 1월 6일 (화) 14:30 ~ 15:20 (약 50분)
참석자: 김루아, 김나연, 이용범/ (중도 참석: 고문님)
작성자: 이용범
1. 회의 개요 및 배경
ԼĀ목적: 공공기관(철도공사 등) 제안을 위한 'AI 기반 조직/목표 관리 시스템' PoC 개발 방향성 확립 및 업무 분장
ԼĀ배경: PoC 개발에 따른 효율적인 R&R 필요
ҰĀ2월 말 데모 시연, 4월 말 완제품 개발이라는 촉박한 일정에 따른 효율적 R&R 필요.
2. 개발 일정 및 목표 (Roadmap)
ԼĀ1차 마일스톤 (2026.02 말): Demo 시연
ҰĀ목표: 제안 발표 시 시연 가능한 수준의 프로토타입
ҰĀ특이사항: 실제 완벽한 로직보다는 시나리오대로 동작하는 '껍데기(Mock-up)' 형태라도 가시적인 결과물이 최우선
ԼĀ2차 마일스톤 (2026.04 말): 실 개발 완료
ҰĀ목표: 실제 기능이 동작하는 시스템 완성
3. 기술적 검토 및 주요 논의 사항
① 음성 인식 (STT) 및 화자 분리
ԼĀ현황: 회의록 작성을 위한 핵심 기능
ԼĀ기술적 난관:
ҰĀ단순 파형 분석만으로는 다자간 회의 시 화자 분리(Speaker Diarization) 정확도가 떨어짐.
ҰĀ비슷한 목소리 톤이 겹칠 경우 식별이 어려움.
ԼĀ대안 (멀티모달 도입 논의):
ҰĀ단순 오디오 처리를 넘어 VLM(Vision Language Model) 접근 방식 제안.
ҰĀ카메라를 통해 입 모양(Lip reading)이나 소리의 방향을 인식하여 화자를 매칭하는 방식 고려
미리 화자의 목소리를 사전학습 시켜 화자 분리의 성능을 높일 수 있는 방법 검토
ԼĀ제약 사항: 외부 API(Google, OpenAI 등) 사용 불가, 오픈소스(On-premise) 모델로만 구현해야 함.
② OCR (광학 문자 인식)
ԼĀ범위: 문서 데이터베이스화.
ԼĀ예상 성능: PDF 등 정형 문서는 인식률이 높으나, 손글씨(Handwritten)는 정확도 저하 우려.
ԼĀ방향: 성능 이슈는 인지하되, 우선순위상 PDF 처리에 집중.
③ 추천 알고리즘 (Recommendation System) 도입 여부
ԼĀ발의 배경: 개인별 업무 연관성이 높은 문서를 우선적으로 매칭하거나, 목표 관리 시 맞춤형 데이터를 제공하기 위함 (넷플릭스/쿠팡 방식 착안).
ԼĀ쟁점:
ҰĀ데이터 부재: 협업 필터링(Collaborative Filtering) 등을 사용하기에는 사용자 로그(User Log)나 평가 데이터(Like/Dislike)가 전무함.
ҰĀ적합성 문제: LLM의 '좋아요/싫어요'는 모델 학습(RLHF)용이지, 개인 취향 분석용 데이터로 보기 어려움.
ԼĀ결론: 별도의 추천 알고리즘 엔진을 구축하는 것은 리소스 낭비일 수 있음. RAG(검색 증강 생성)의 검색 로직을 고도화하거나 룰 베이스(Rule-based)로 처리하는 것이 현실적임.
④ 디지털 트윈 (Digital Twin) 개념 접목
ԼĀ방향성: 단순 조직도가 아닌 가상 공간(Virtual Space)에 실존 인물을 매핑.
ԼĀ기능: 가상 공간 내에서 결재, 업무 흐름, 조직 관리가 시뮬레이션 되는 형태로 경쟁사 대비 차별화 필요
4. 업무 분장 (R&R) 재정립
초기에는 기능 단위(음성/OCR)로 나누려 했으나, 기술 계층(Layer) 단위로 역할을 나누는 것이 효율적이라는 결론에 도달함.

| 구분         | 담당자      | 역할 및 책임 (R&R)                         |
| ---------- | -------- | ------------------------------------- |
| Model Part | 이용범, 조기정 | - 오픈소스 AI 모델(STT, OCR, LLM 등) 선정 및 튜닝 |
| Agent      | 김루아, 김나연 | - 모델을 활용한 서비스 로직 및 워크플로우 설계           |

변경 사유: 모델 자체의 성능을 높이는 작업(Model)과 그 모델을 가져와서 비즈니스 로직을 적용하는 작업(Agent)의 성격이 다르므로, 이를 분리하여 협업하는 구조가 효율적
5. 이슈 및 리스크 (Risk Management)
̠Ā프로젝트 중복 수행 불가:
ҰĀ현재 '보안 관제 시스템(N-SI)'의 2차 고도화(Graph DB 구축, 미들웨어 연동) 일정이 잡혀 있음.
ҰĀPoC 일정(2월 데모)이 매우 촉박하여 두 프로젝트 병행은 불가능함
ҰĀ내일(수) 주간회의 시 'PoC 개발'을 위한 기존 프로젝트 일시 중단(Hold) 승인 요청 필요.
̠Ā기획팀과의 소통:
ҰĀ개발팀 내부 R&R은 정리되었으나, 인터페이스 정의 및 데이터 연동 방식 협의가 아직 안 됨.
6. 향후 계획 (Next Step)
ԼĀ금일 (01.06): 회의록 정리 및 고문님 보고
ԼĀ익일 (01.07): 주간 회의 시 기존 프로젝트(N-SI) 중단 및 PoC 집중 체제 전환 공식 건의.
ԼĀ금주 중: 기획팀, 미들웨어팀과 미팅하여 API 연동 규격 및 데이터 흐름 협의
[참고] 용어 정리
ԼĀVLM (Vision-Language Model): 이미지/영상과 텍스트를 함께 이해하는 멀티모달 모델.
ԼĀSpeaker Diarization: 오디오 스트림에서 "누가 언제 말했는지"를 식별하는 기술.
ԼĀRAG (Retrieval-Augmented Generation): LLM이 외부 지식 베이스(문서 등)를 검색하여 답변 정확도를 높이는 기술.
